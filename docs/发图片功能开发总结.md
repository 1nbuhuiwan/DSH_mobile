# DSH 手机端 · 发图片功能 开发全过程总结

> 坐标：`/Users/Admin/Documents/dshaness/dsh-mobile/`（Kotlin + 系统 WebView 的轻量浏览器）
> 目标：让手机在 DeepSeek 会话里**选图 → 能真正把图发进会话、并被智能体收到**。

---

## 一、最终成果（一句话）

手机 `+` 按钮 → 选图 → 弹出**圆角输入框**填描述（可留空）→ 页面把图压缩到 ≤64KB → `POST /api/rpc` 调 Harness 的 `session.prompt`，content 带 `{type:'image', data(base64), mediaType}` + 文字 → 直接进会话、智能体（大模型）收到图片和文字。

**完全绕开了 DeepSeek 网页端那个"从未真正生效"的收图 UI。**

---

## 二、问题的本质（为什么手机发图这么难）

深挖 Harness 源码后发现，真正卡点不在 App，而在 **DeepSeek Harness 网页端本身**：

1. Harness 的**图片存储/接入层其实一直开着**（`attachments.imageLimits` 有默认值），模型层也支持 `{type:'image', attachment:{bytes, mediaType}}` 内容块——**Harness 完全能收图**。
2. 但网页端那个"拖图/选图"组件 `ComposerAttachments`，只有会话被判定为**支持图片（`vision`/`canAcceptDrop` 为 true）**时才挂载。
3. 你的模型 `DeepSeek-V4-Flash-Vision-Exp` 没被 Harness 识别为视觉模型 → `vision=false` → 收图组件不挂载。**所以连电脑端拖图都无法上传**（已验证），手机端更不可能通过网页 UI 发图。
4. 且网页输入框是纯文本 `<textarea>`，**无法粘贴/接收图片**（这解释了"粘贴出来是乱码"）。

结论：**这条路被 Harness 的模型能力判定 + 网页 UI 设计卡死，任何"模拟网页 UI"的做法都到不了终点**。唯一正解是**绕开网页 UI，直接调 Harness 的会话接口**。

## 三、完整过程时间线（问题 → 原因 → 尝试 → 解决）

### 阶段 0：WebView 文件选择器（`onShowFileChooser`）
- **做法**：在 `WebChromeClient.onShowFileChooser` 里弹出系统文件/相册选择器。
- **失败**：用户反馈——**DeepSeek 聊天界面里看不到任何"发附件"按钮**（`onShowFileChooser` 只在网页真的去点 `<input type=file>` 时才触发，而网页根本没这个入口）。

### 阶段 1：注入「+」按钮（JS 注入）
- **做法**：注入脚本在 DeepSeek 输入区左侧放一个蓝色「+」。
- **bug ①：按钮盖住输入框**（fixed overlay 定位遮住了对话框）。
  - 原因：用 `position:fixed` 硬定位在输入区左下。
  - 解决：改为**把「+」作为输入行（横向 flex 容器）的第一个子元素**（`flex:0 0 auto`，占位不遮输入），并加"找不到横向行就不注入"的兜底。
- **bug ②：点了能选图、有震动，但**没有缩略图**、发消息也没上传**。
  - 排查：打日志发现走了"**兜底路径**"（`findPageFileInput` 找不到任何 DeepSeek 文件输入框），图片进了**孤儿输入框**，DeepSeek 从未收到。

### 阶段 2：剪贴板方案（你提议的）
- **做法**：选图后 `ClipData.newUri(contentResolver,...)` 放进系统剪贴板，聚焦输入框让用户"长按粘贴"。
- **失败**：粘贴出来是**乱码**。
  - 原因（源码证实）：DeepSeek 输入框是**纯文本 `<textarea>`**，无法容纳图片，粘贴把图片字节当文本塞进去。

### 阶段 3：深挖 Harness 源码，定位根因
读了 `dsh-llm`、`dsh-attachment`、`dsh-api-session-controller`、`dsh-web-frontend` 等包，确认：
- `attachments.imageLimits` 始终开启；模型支持图片内容块。
- **唯一闸门**是会话的 `vision` 能力 → 决定 `ComposerAttachments` 是否挂载、`canAcceptDrop` 是否为 true。
- 对自定义模型名，Harness 判成无视觉。

### 阶段 4：合成拖拽（drop）事件
- **做法**：既然 DeepSeek 在 `document` 上监听 `drop` 收图，就构造 `new DragEvent('drop',{dataTransfer})`（及 `Event`+`defineProperty` 兜底）派发到 `document`。
- **失败**：日志 `dtSeen=true seenTypes=Files handled=false`——drop 被派发到 document 了，但 DeepSeek 的 `onDrop` 没处理。
  - **根因**：合成 drop 事件在 Android WebView 里**无法真正携带"拖拽处理器可接受的文件"**（浏览器安全机制），且该组件本就没挂载（`vision=false`）。
  - 这条"模拟网页收图"的路线彻底走不通。

### 阶段 5（成功）：直接调 Harness 会话接口 `/api/rpc` 的 `session.prompt`
- **发现**：桥接服务 `/api/rpc` 有白名单，其中 **`session.prompt`** 就是"向会话发一条消息"，且 content 支持 `{type:'image', data, mediaType, name}`。手机 WebView 与 Harness 同源、带登录 Cookie，`fetch('/api/rpc')` 自带鉴权，**能绕过网页收图 UI**。
- **对应子问题**：

| 子问题 | 原因 | 尝试 | 解决 |
|---|---|---|---|
| **拿 sessionId** | 会话 id 不在 URL/资源里 | 试 `performance.getEntriesByType('resource')`、`location` | 用 `session.list` RPC；后又改为直接读网页全局变量 **`activeSession`**（= 手机当前打开的会话，最准） |
| **发到错误会话** | `session.list` 里按"最近更新"选会话，但你正在看的是另一个会话 | — | 改读 **`activeSession`**，发到手机上**正在看**的会话 |
| **请求体太大 (500)** | 桥接 `/api/rpc` 上限 = **64KB**（`MAX_BODY_BYTES=64*1024`），108KB 图 base64 后都超 | — | 页面里**先把图压缩**：canvas 缩到 ≤1024px、逐级降 JPEG 质量，直到 base64 ≤56KB |
| **图片读不出来 ([object Event])** | `URL.createObjectURL(file)` 建的 blob URL，WebView 的 Image 加载器读不了 content:// 文件 | — | 改用 **`FileReader.readAsDataURL`**（直接 data URL）→ `Image`，稳定 |
| **默认文案固定** | 发图自动带"请查看这张图片" | — | 改成弹**文本输入框**让你自己写描述，可留空 |
| **输入框太丑** | 原生 `AlertDialog` + 裸 `EditText` 不统一 | — | 自定义布局：圆角卡片 + 圆角输入框 + 次级/品牌蓝按钮，与全局 DeepSeek 设计令牌一致 |

## 四、顺带发现并修复的其它问题

- **房子图标错误**：之前点它是"回到当前会话"；用户要的是"回去选/新建会话"。
  - 解决：房子图标 → `showSessionList()`（网页里切到会话列表的函数）。
- **返回键退出再进 App 一片空白**：重新创建 Activity 后 WebView 是空的（没加载页面）。
  - 解决：`onCreate` 里自动 `loadUrl(savedUrl)`（Cookie 已持久化，能直接恢复会话且不掉线）。
- **清理调试代码**：移除 `glog` 逐步骤日志、`DebugLog`、没用到的函数与字符串，只留成功/失败提示。

## 五、经验 / 结论

1. **浏览器安全限制，无法用"模拟网页事件"把文件喂给网页的上传控件**（合成 drop/paste 不带真文件、textarea 收不了图）。任何"在网页里伪造收图"的路线都走不通。
2. **碰到"网页 UI 没暴露但我们想要的能力"时，优先去找它后端真实用的接口**。`/api/rpc` + `session.prompt` 就是 Harness 自己收消息的通道，绕过 UI 门控直连——这是最稳的正解。
3. **手机 WebView 与 Harness 同源 + 带登录 Cookie**，是能直接调 `session.prompt` 的关键前提（免额外鉴权）。
4. **读源码定位根因**：从 "`ComposerAttachments` 不挂载" → 找到 `vision` 门控 → 放弃 UI 路线 → 找到会话接口，这条链是本次能打通的决定性因素。
5. 一个客观限制：受桌面端 `/api/rpc` **64KB** 上限，发图会被压成较小 JPEG；要发高清原图需调大桌面端上限（要动桌面端）。且 Harness 附件模型**只有图片**，Word/PPT 无法发送。
